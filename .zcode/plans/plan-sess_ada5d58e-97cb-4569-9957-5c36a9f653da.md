## 实施计划（改动文件：index.js 为主，style.css 少量）

### 功能 1：倒退一轮（回到上一个小纸条）
现状：`rewind-turn` 的完整处理逻辑已存在（index.js:6054-6065，含减回合、重注入、复活已结束事件、保存），但**没有任何按钮绑定它**。只需接线：
1. 悬浮胶囊 `updateFloatingCapsule`（index.js:5998-6008）在「推进」旁加「倒退」按钮（`data-capsule-action="rewind-turn"`），并微调移动端媒体查询样式（style.css:2824 附近）防拥挤。
2. 引擎面板卡片操作行（index.js:6123-6130）加「倒退一轮」按钮，同样绑 rewind-turn。
3. 行为已满足你的要求：`currentTurn` 减一但**不低于 1**；事件已结束也能退回来重新激活（isActive=true）；重注入上一回合的纸条。

### 功能 2：悬浮胶囊可拖动 + 记住位置
1. `DEFAULT_SETTINGS`（index.js:103-142）新增 `capsuleX/capsuleY`（默认 null）。
2. style.css `.se-floating-capsule`（1849-1867）：去掉 `translateX(-50%)` 水平居中，改由 JS 用 left/top 定位；加 `cursor: grab`；隐藏动画兼容（隐藏态保留 opacity/translateY）。
3. 新增 `applyCapsulePosition()`：有保存值则钳制在可视区内恢复，无则默认顶部居中；在 `updateFloatingCapsule`（显示时）与 `window.resize`（index.js:1189-1205 处，与 FAB/面板一起）调用。
4. 新增 `makeCapsuleDraggable(capsule)`：完全仿照现有 `makeFabDraggable`（index.js:2051-2136）——mousedown/touchstart → move（8px 阈值防触屏误触）→ 边界钳制视口内 → mouseup 时把 `capsuleX/capsuleY` 写入 settings 并 `persistSettings`；拖拽后拦截 click 防止误触「推进/结束」。
5. 在 `ensureFloatingCapsule`（index.js:5957-5974，胶囊常驻元素只创建一次）里绑定一次拖拽。

### 功能 3：回合上限变动时，剩余纸条均摊剩余回合（完整实现）
替换现在「全局等比例」的映射（index.js:5595-5597、5659），改为**锚点式均匀分配计划**：

**核心数据结构**：`activeEvent.stagePlan = number[][]`，`stagePlan[t-1]` = 第 t 回合应注入的纸条索引列表。
- 新增 `splitEvenly(total, parts)`：均分 `parts` 组，余数依次给**最后的组**。例：`splitEvenly(8,7)=[1,1,1,1,1,1,2]`、`splitEvenly(8,3)=[2,3,3]`。
- 新增 `buildStagePlan(active)`（事件激活/无计划时）：从第 1 回合整体均匀分配——纸条比回合多 → 每回合合并多张（余数给末尾回合，**保证终局回合必含最后一张**）；回合比纸条多 → 每张纸条跨多回合（余数给末尾纸条）。
- 新增 `rebuildStagePlan(active)`（maxTurns 变化时）：**保留已演部分** `stagePlan[0..X-2]`（回退、历史显示不失真）；**当前回合固定为正在演的那张纸条**（C = 旧计划当前回合最后一张，旧计划缺失时用原比例公式在 (X,M) 处的索引兜底，保证升级/无计划存档不跳纸）；未来回合把未演纸条（C+1..最后）用 `splitEvenly` 均摊到 X+1..M；若已无未演纸条，最后一张延续到全部剩余回合。

效果对照你的例子（全部命中）：
- 8 纸条、8→7 回合：`1、2、3、4、5、6、7-8`（第 7 回合合并纸条 7+8）。
- 已演到纸条 2、4→8 回合：纸条 3 演 3 回合、纸条 4 演 3 回合。
- 3 张纸条、8 回合：`2/3/3` 回合。
- 常规 N==M 时退化为 1:1，与现有行为完全一致。

**接线改动**：
1. `activateEvent`（index.js:5484-5493）：创建 active 时 `buildStagePlan`；加载到无计划的旧 active 时自动重建。
2. `buildSegmentPrompt`（index.js:5586-5628）：改读 `stagePlan` 得到本回合纸条组；单张=原逻辑；多张=内容拼接（终局回合沿用现有「终局收束判定」指令块 + 后台档案 + 结局判定），同一纸条跨多回合的后续回合在正文头部加一行「承接上一回合，同一张小纸条继续演绎」提示。
3. `getActiveStageInfo`（index.js:5653-5662）：改用 `stagePlan`，新增 `stageIndexes / stageLabel`（如「小纸条 7-8」）；现有调用方（胶囊、引擎卡片）只取 `curTurn/maxTurns/isFinalStage`，无需改。
4. `handleCapsuleAction` 的 `add-turn / sub-turn`（index.js:6030-6053）：改上限后调 `rebuildStagePlan` 再 `registerInjection`。
5. `changeEventTurns / setEventTurns`（index.js:3329-3383，事件卡片与弹窗里的 -1/+1/应用 共用；实现时确认弹窗按钮走的是这两个函数，若有独立处理器则同样挂上）：isActive 时也 `rebuildStagePlan`。
6. 纸条查看弹窗 `openStageModalForEvent`（index.js:6233-6238 的 `currentStageIdx`、6277+ 高亮循环）：活动事件改用 `stagePlan` 高亮当前回合的全部纸条（合并回合显示「本回合合并多张纸条」）。
7. `advance / climax / rewind / reactivate / MESSAGE_DELETED 回退 / CHAT_CHANGED` 均只**读** stagePlan，天然正确，逻辑不变。

**持久化**：`stagePlan` 是 activeEvent 上的普通字段，`saveChatState`（index.js:528-541）随聊天元数据整个序列化，无需额外代码。
